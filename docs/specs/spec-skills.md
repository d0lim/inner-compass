# Inner Compass 스킬 명세서

Inner Compass 플러그인에 포함된 세 가지 스킬의 설계 명세입니다.

---

## 1. inner-compass-pattern-detect

### 기본 정보

| 항목 | 내용 |
|------|------|
| 이름 | `inner-compass-pattern-detect` |
| 설명 | 생각 조각들에서 반복 패턴, 감정 클러스터, 갈등 쌍을 감지 |
| 트리거 | `생각 정리`, `패턴`, `반복`, `계속 같은`, `또 이런` |

### 역할

사용자가 여러 생각 조각을 던졌을 때 그 안에서 숨겨진 구조를 찾아낸다. 단순 나열이 아니라 생각들 사이의 관계와 경향성을 파악하는 것이 목적이다.

### 감지 항목 (5가지)

**1. 반복 주제**
표현은 다르지만 동일한 핵심을 가리키는 생각들을 묶는다. 같은 주제를 여러 각도에서 반복해서 언급한다는 것은 해당 주제가 사용자에게 미해결 상태임을 시사한다.
- 예: `"시간이 없어"` + `"너무 많은 걸 하고 있어"` → 공통 주제: **과부하**

**2. 감정 클러스터**
비슷한 감정 톤을 가진 생각들을 계열별로 분류한다. 어떤 감정군이 지배적인지 파악해 사용자의 현재 심리적 지형을 드러낸다.
- 분류 예시: 불안 계열 / 욕구 계열 / 회피 계열

**3. 갈등 쌍**
서로 모순되는 두 생각을 한 쌍으로 묶어 양가감정의 존재를 식별한다. 갈등 쌍은 사용자가 의식하지 못한 내면 긴장의 신호다.
- 예: `"새로운 걸 시작하고 싶어"` + `"기존 것도 못 마무리하는데"` → 시작 욕구 vs 완수 부담

**4. 에너지 방향**
생각들이 주로 향하는 시간축을 분석한다. 과거 회귀 / 현재 불안 / 미래 기대 중 어디에 심리적 무게중심이 있는지 파악한다.

**5. 부재 영역**
언급되지 않았지만 일반적으로 중요한 영역(관계, 건강, 재정 등)이 완전히 빠져 있을 경우 이를 표시한다. 의식적 회피일 가능성을 열어두고 탐색의 단서로 활용한다.

### 사용 맥락

`inner-compass-socratic` 에이전트의 초기 분석 단계에서 자동으로 활성화된다. 사용자가 생각을 쏟아낸 직후, 소크라테스식 탐색에 들어가기 전에 먼저 패턴 지도를 그리는 역할을 한다.

## 2. inner-compass-ontological-analysis

### 기본 정보

| 항목 | 내용 |
|------|------|
| 이름 | `inner-compass-ontological-analysis` |
| 설명 | 표면적 현상과 본질적 원인을 분리하는 존재론적 분석 |
| 트리거 | `본질`, `근본 원인`, `왜 이러는 걸까`, `진짜 문제` |

### 역할

사용자가 말하는 것이 실제 문제의 전부가 아닐 수 있다는 전제 아래, 표면적 호소와 그 아래에 있는 진짜 원인을 층위별로 분리해 드러낸다.

### 증상 vs 원인 분리

분석은 세 층위로 구분된다:

- **증상 (표면)**: 사용자가 직접 말하거나 의식하는 것
- **원인 (중간)**: 증상 아래 추론 가능한 감정·욕구
- **본질 (깊이)**: 원인 아래 존재하는 가장 근원적인 욕구 또는 두려움

표면에서 제시된 문제만 다루면 같은 증상이 반복된다. 본질 층위까지 내려가야 지속적 변화가 가능하다.

### 본질 추출 질문법 (4가지)

본질에 도달하기 위해 다음 네 가지 질문 프레임을 순차적으로 또는 선택적으로 적용한다:

1. **의존 관계 파악**: "이것을 제거하면 무엇이 달라지는가?" — 해당 요소가 다른 무엇에 기대고 있는지 드러낸다.
2. **필수/부수 분리**: "이것이 없어도 불편한가?" — 진짜 필요인지, 부수적 집착인지 구분한다.
3. **시간축 필터링**: "10년 후에도 중요한가?" — 일시적 감정과 지속적 가치를 분리한다.
4. **핵심 가치 도출**: "이것의 반대는 무엇인가?" — 반대 개념을 통해 사용자가 실제로 지키려는 가치를 역추적한다.

### 출력 구조 (3-layer)

분석 결과는 반드시 3층 구조로 제시한다:

```
Layer 1 (표면): 사용자가 직접 진술한 내용
Layer 2 (중간): 표면 아래 추론된 감정 또는 욕구
Layer 3 (본질): 가장 깊은 존재론적 욕구 또는 두려움
```

이 구조는 사용자가 자신의 내면을 시각적으로 확인할 수 있게 하며, 어느 층위에서 다루어야 할지 스스로 선택할 수 있는 정보를 제공한다.

## 3. inner-compass-obsidian-export

### 기본 정보

| 항목 | 내용 |
|------|------|
| 이름 | `inner-compass-obsidian-export` |
| 설명 | 세션 결과를 Obsidian 호환 마크다운으로 최적화 |
| 트리거 | `저장`, `obsidian`, `내보내기`, `노트` |

### 역할

crystallizer가 생성한 출력물을 Obsidian에서 바로 활용 가능한 형태로 보장한다. 내용을 변경하는 것이 아니라 포맷과 구조가 Obsidian의 기능(그래프 뷰, 백링크, callout 등)과 호환되도록 만드는 것이 목적이다.

### Obsidian 호환 규칙 (5가지)

**1. YAML frontmatter 필수**
모든 파일은 `date`, `state`, `tags`, `mode` 등의 필드를 포함한 YAML frontmatter로 시작해야 한다. Obsidian의 메타데이터 기반 필터링과 검색에 활용된다.

**2. 태그는 frontmatter 배열로**
태그는 frontmatter의 `tags` 배열에만 작성한다. 본문 내 인라인 `#태그` 형식은 사용하지 않는다. 태그 관리의 일관성을 위해 단일 위치에 집중한다.

**3. 관련 세션 연결은 wikilink 형식**
다른 세션이나 노트를 참조할 때는 `[[파일명]]` 형식의 wikilink를 사용한다. Obsidian의 그래프 뷰와 백링크 기능이 이 형식을 기반으로 작동한다.

**4. 나침반은 Obsidian callout 문법**
Inner Compass의 핵심 출력인 나침반(방향 제시)은 다음 callout 문법으로 작성한다:
```
> [!compass]
> 내용
```

**5. 비유는 이탤릭 인용 형식**
세션에서 도출된 비유 문장은 이탤릭 인용 형식으로 표기한다:
```
*"비유 문장"*
```

### 파일명 규칙

생성되는 파일의 이름은 세션 시작 시각을 기준으로 24시간 형식으로 결정한다:

| 모드 | 파일명 형식 |
|------|-------------|
| 기본 | `YYYY-MM-DD-HHmm.md` |
| quick 모드 | `YYYY-MM-DD-HHmm-quick.md` |
| deep 모드 | `YYYY-MM-DD-HHmm-deep.md` |

파일명에 모드 정보를 포함함으로써 Obsidian에서 별도의 태그 필터 없이도 세션 유형을 식별할 수 있다.

# Inner Compass — 커맨드 스펙

> 각 slash command의 동작 방식을 설명합니다. 페이즈별 세부 흐름은 `spec-phase-flow.md`를 참조하세요.

---

## 공통 전제

모든 커맨드는 실행 시 가장 먼저 `~/.inner-compass/config.md`를 읽어 세션 저장 경로를 확인합니다. 설정 파일이 없으면 `/reflect-setup`을 먼저 실행하도록 안내하고 중단합니다.

---

## `/reflect`

표준 탐색 세션. 생각 수집 → 소크라테스식 질문 → 결정화 → 리뷰 → 저장의 전 과정을 거칩니다.

### Pre-phase: 마이그레이션 확인

세션 저장 경로에서 파일 존재 여부에 따라 세 가지로 분기합니다.

- `roots.md`가 없고 `patterns.md`가 있는 경우: `patterns.md`를 `roots.md` 형식으로 변환합니다. 패턴명은 뿌리 이름으로, 설명은 메모로, 관련 세션 수는 등장 횟수로 매핑합니다. 표면 변형은 빈 리스트, 추이는 "관찰 중"으로 초기화합니다. 변환 후 `patterns.md`는 삭제하지 않고 보존합니다.
- `roots.md`와 `patterns.md` 둘 다 있는 경우: `roots.md`만 사용합니다.
- 둘 다 없는 경우: 첫 세션으로 간주하고 빈 상태로 진행합니다.

### Pre-phase: Context 로드

마이그레이션 확인 후 `roots.md`를 읽습니다. 파싱이 불가능하면 빈 상태로 취급하고 세션 파일에 경고를 기록합니다.

이어서 세션 저장 경로에서 가장 최근 세션 파일 1개를 읽습니다. 나침반 섹션이 없는 파일은 건너뛰고 그 다음 최근 파일로 폴백합니다. 나침반 섹션과 `state`(상태 명명) 값을 추출합니다.

### Phase 0: 수집

`inner-compass-collector` 에이전트에 위임하여 사용자의 생각 조각을 수집합니다. `$ARGUMENTS`가 있으면 첫 번째 생각으로 사용합니다. 최소 3개의 생각이 모이면 다음 단계를 제안하며, 사용자가 종료 신호를 주면 수집을 마칩니다.

### Phase 1: 탐색

`inner-compass-socratic` 에이전트에 수집된 생각, roots.md, 최근 세션 나침반을 전달합니다. 에이전트가 반환하는 질문 중 2–3개를 사용자에게 제시하고, 답변을 받아 후속 질문으로 이어지는 방식으로 2–3라운드를 진행합니다.

### Phase 2: 결정화

`inner-compass-crystallizer` 에이전트에 원본 생각, 전체 대화 기록, roots.md, 저장 경로, 모드(`standard`)를 전달합니다. 에이전트는 결정화 결과와 뿌리 매칭 분석(`[roots_update]` 구조)을 반환합니다. 파일 저장과 roots.md 갱신은 이 단계에서 수행하지 않습니다.

### Phase 2.5: 리뷰 분기

결정화 결과를 사용자에게 보여주고 세 가지 선택지를 제시합니다.

**(1) 저장:** Phase 3으로 진행합니다.

**(2) 수정:** 사용자에게 수정할 부분을 물은 뒤 `inner-compass-crystallizer`를 수정 모드로 호출합니다. 이전 결정화 결과와 사용자 피드백을 전달하여 지적된 부분만 수정합니다. 수정된 결과로 다시 리뷰 분기(Phase 2.5)부터 반복합니다.

**(3) 새로운 생각:** 사용자에게 추가 생각을 입력받은 뒤 `inner-compass-socratic`을 2차 탐색 모드로 호출합니다. 원본 생각, 1차 대화 이력, 현재 결정화 결과, 새로운 생각, roots.md를 함께 전달하며, 1차에서 다룬 질문은 반복하지 않도록 지시합니다. 2차 탐색이 끝나면 Phase 2(결정화)로 돌아가되, crystallizer에 전달하는 대화 기록에 2차 탐색 내용도 포함합니다. 결정화 후 다시 Phase 2.5로 돌아갑니다.

### Phase 3: 저장 및 완료

**세션 파일 저장:** 파일명은 `YYYY-MM-DD-HHmm.md` 형식으로 현재 시각을 사용합니다. 리뷰 분기에서 수정이 한 번이라도 발생한 경우 frontmatter에 다음 필드를 추가합니다.

```yaml
revised: true
revision_count: {수정 횟수}
revision_history:
  - type: correction | exploration
    trigger: "{사용자가 말한 수정/탐색 계기 요약}"
```

**roots.md 갱신:** crystallizer가 반환한 `[roots_update]` 분석 결과를 기반으로 roots.md를 갱신합니다. 최종 수락된 결정화 결과 기준으로 한 번만 수행합니다. roots.md 전체를 읽고 업데이트된 버전으로 파일 전체를 다시 씁니다.

- `matched` 항목: 해당 뿌리에 표면 변형을 추가하고, 추이를 갱신하며, 등장 횟수를 늘리고, 관련 세션 링크를 추가합니다.
- `new` 항목: 새 뿌리로 등록합니다. 추이는 "관찰 중"으로 초기화합니다.
- `ambiguous` 항목: 세션 frontmatter에 `연관 가능: {뿌리명}`을 표시합니다. 2회 연속 세션에서 같은 연관이 감지되면 매칭으로 승격하고, 3회 세션 동안 재등장하지 않으면 연관 표시를 삭제합니다.
- `resolved` 항목: 해소된 뿌리 섹션으로 이동하고 해소 계기를 기록합니다.
- roots.md가 손상되었거나 파싱 불가능하면 빈 상태로 취급하고 세션 파일에 경고를 기록합니다.

**완료 안내:** 저장 완료를 알리고, 궤적 섹션에서 반복 중인 뿌리가 있으면 간략히 언급합니다.

## `/reflect-quick`

빠른 내면 탐색. 질문 1회로 간략하게 상태를 진단합니다.

### Pre-phase: Context 로드

`/reflect`의 마이그레이션 확인과 동일한 절차를 따릅니다. roots.md와 가장 최근 세션의 나침반 + state를 로드합니다.

`$ARGUMENTS`가 있으면 첫 번째 생각으로 사용합니다. 없으면 생각 하나만 입력받습니다.

### 플로우

1. 사용자 입력, roots.md, 최근 세션 나침반을 `inner-compass-socratic` 에이전트에 전달합니다.
2. 에이전트 질문 1개만 제시하고 답변 1회를 받습니다.
3. `inner-compass-crystallizer` 에이전트에 위임하여 간략 진단합니다. roots.md를 함께 전달하며 모드는 `quick`으로 지정합니다.
4. 결과를 세션 저장 경로의 `YYYY-MM-DD-HHmm-quick.md`에 저장합니다.

### 간이 모드 적용 범위

| 기능 | 적용 여부 |
|---|---|
| roots.md 로드 + 뿌리 인지 질문 | O (1라운드) |
| 표면→뿌리 맵 | X (생략) |
| 뿌리 매칭 + roots.md 갱신 | O (본질 진단에서 뿌리 추출) |
| 궤적 섹션 | O (간략 — 반복 뿌리만 표시) |

## `/reflect-deep`

심층 내면 탐색. 질문 5회 이상으로 깊이 파고듭니다.

### Pre-phase: Context 로드

`/reflect`의 마이그레이션 확인과 동일한 절차를 따릅니다. roots.md와 가장 최근 세션의 나침반 + state를 로드합니다.

### 플로우

1. **생각 수집:** `inner-compass-collector` 에이전트로 생각을 수집합니다. 최소 5개를 권장합니다.
2. **심층 탐색:** `inner-compass-socratic` 에이전트로 5라운드 이상 대화합니다. roots.md와 최근 나침반을 함께 전달하며, 매 라운드마다 존재론적 분석을 강화하고 "이것이 증상인가 원인인가?" 계열 질문을 중심으로 진행합니다. 과거 뿌리가 반복될 경우 더 깊이 파고듭니다.
3. **심층 결정화:** `inner-compass-crystallizer` 에이전트로 진단합니다. roots.md를 함께 전달하며 모드는 `deep`으로 지정합니다. 표준 진단에 더해 시간축 분석(과거→현재→미래)과 가치관 충돌 맵을 포함하며, 궤적 섹션도 전체 + 시간축 분석을 포함합니다. crystallizer는 결과와 뿌리 매칭 분석을 반환하며 파일을 저장하지 않습니다.
4. **리뷰 분기:** `/reflect`와 동일한 구조입니다. (1) 저장, (2) crystallizer 수정 모드, (3) socratic 2차 탐색(5+라운드) 중 선택하며, 수정/탐색 후 다시 리뷰 분기로 반복합니다.
5. **저장 및 완료:** 파일명은 `YYYY-MM-DD-HHmm-deep.md`입니다. 수정이 발생한 경우 frontmatter에 `revised`, `revision_count`, `revision_history`를 추가합니다. roots.md 갱신은 최종 결과 기준으로 한 번만 수행합니다.

## `/reflect-review`

과거 탐색 세션들을 회고합니다.

### 플로우

1. 세션 저장 경로의 세션 파일들과 roots.md를 읽습니다.
2. `$ARGUMENTS`가 있으면 다음 기준으로 세션을 필터링합니다. 없으면 최근 5개 세션을 사용합니다.
   - 날짜: "이번 달", "최근 3개", "3월" 등
   - 키워드: "커리어", "불안" 등
   - 뿌리 이름: roots.md의 뿌리명으로 필터링
3. `inner-compass-retrospective` 에이전트에 세션 파일들과 roots.md를 전달합니다. 에이전트는 시간에 따른 상태 변화, 뿌리 단위의 장기 패턴, 표면 변형의 시간순 변화를 분석합니다.
4. 장기적 인사이트를 사용자에게 제시합니다.

## `/reflect-setup`

Inner Compass 초기 설정을 진행합니다. 최초 1회 실행합니다.

### 플로우

1. **기존 설정 확인:** `~/.inner-compass/config.md`가 이미 존재하면 현재 설정을 보여주고 변경 여부를 묻습니다.
2. **Obsidian vault 경로 입력:** 사용자에게 vault 경로를 물어봅니다. 경로가 입력된 경우 해당 경로의 존재 여부를 확인합니다. 경로가 존재하면 `{vault}/Inner-Compass/sessions/` 디렉토리를 생성합니다. 경로가 존재하지 않으면 다시 확인을 요청합니다. 빈 입력(Enter)이면 기본 경로 `~/.inner-compass/sessions/`를 사용합니다.
3. **디렉토리 생성:** `~/.inner-compass/`와 세션 저장 디렉토리를 생성합니다.
4. **설정 저장:** `~/.inner-compass/config.md`에 설정을 저장합니다.
5. **완료 안내:** 설정이 완료된 세션 저장 경로를 알리고 `/reflect`로 탐색을 시작하도록 안내합니다.

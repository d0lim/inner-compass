# Retrospective Loop Framework Design

**Goal:** 매 세션마다 과거 context를 자동으로 참조하여, 세션이 쌓일수록 질문의 깊이와 진단의 연속성이 성장하는 구조를 만든다.

**Architecture:** Root-Centric Registry (Approach B). 표면이 아닌 뿌리를 축으로 지식이 누적된다. 매 세션마다 roots.md를 읽고 갱신하는 루프가 자동으로 돈다.

**핵심 원칙:**
- 매칭/추이 판단은 규칙이 아닌 에이전트의 맥락 기반 판단
- 매 세션 자동. 사용자가 의식할 필요 없음
- 해소된 뿌리는 별도 섹션으로 분리하여 향후 growth.md 마이그레이션 대비

---

## 1. 루프 흐름

```
매 세션 시작
  ↓
[1] roots.md + 최근 세션 로드 (lightweight)
  ↓
[2] collector: 생각 수집 (변경 없음)
  ↓
[3] socratic: 과거 뿌리 context 포함하여 질문
    - "이전에도 비슷한 뿌리가 있었는데..."
    - 시간 간격 길면 "지난 나침반의 다음 한 걸음은?"
  ↓
[4] crystallizer: 진단 생성 + 뿌리 매칭
    - 새 표면→뿌리 맵 생성
    - 기존 roots.md와 매칭
    - 같은 뿌리 → 표면 변형 추가 + 추이 판단
    - 새 뿌리 → 등록
    - "3개월째 옷만 바꿔 입는 주제" 통찰 포함
  ↓
[5] roots.md 갱신 + 세션 파일 저장
```

## 2. roots.md 데이터 구조

위치: `{sessions_dir}/roots.md` (기존 `patterns.md`를 대체)
- 기본 경로: `~/.inner-compass/roots.md`
- Obsidian vault 설정 시: `{vault}/Inner-Compass/roots.md`
- `patterns.md`와 같은 레벨에 위치

```markdown
---
last_updated: 2026-03-22T18:30
total_sessions: 12
---

# 뿌리 레지스트리

## 뿌리: 과부하
- 표면 변형: ["시간이 없어", "새 프로젝트 하고 싶어", "번아웃 올 것 같아"]
- 최초 감지: 2026-01-15
- 최근 등장: 2026-03-22
- 등장 횟수: 4회
- 추이: 유지
- 관련 세션: [[2026-01-15-1430]], [[2026-02-10-0900]], [[2026-03-01-2100]], [[2026-03-22-0900]]
- 메모: 표면은 계속 바뀌지만 "한정된 시간에 너무 많은 것"이라는 본질이 반복됨

## 뿌리: 방향 상실
- 표면 변형: ["뭘 해야 할지 모르겠어", "커리어가 불안해"]
- 최초 감지: 2026-02-10
- 최근 등장: 2026-02-10
- 등장 횟수: 1회
- 추이: 관찰 중
- 관련 세션: [[2026-02-10-0900]]
- 메모: ~

## 해소된 뿌리

### 뿌리: 대인관계 불안
- 표면 변형: ["팀원과 갈등", "혼자인 느낌"]
- 활성 기간: 2026-01-15 ~ 2026-02-20
- 해소 계기: 직접 대화 후 관계 회복
- 관련 세션: [[2026-01-15-1430]], [[2026-01-28-1100]], [[2026-02-20-1500]]
```

### 필드 설명

| 필드 | 설명 |
|------|------|
| `표면 변형` | 이 뿌리가 나타난 모든 표면적 표현들 (세션마다 추가) |
| `추이` | `악화` / `유지` / `개선` / `관찰 중` / `해소됨` |
| `메모` | 에이전트가 세션마다 누적하는 자유 텍스트 관찰 |
| `해소 계기` | 해소된 뿌리에만. 무엇이 변화를 만들었는지 기록 |

### 추이 판단 가이드라인 (crystallizer용)

- 표면이 더 강렬해짐 → **악화**
- 비슷한 강도로 반복 → **유지**
- 표면이 약해지거나 구체적 해결 시도 언급 → **개선**
- 1회만 등장, 판단 근거 부족 → **관찰 중**
- 사용자가 "이건 이제 괜찮아" 언급 → **해소됨** 후보 (확인 질문 후 확정)

## 3. 에이전트별 변경사항

### 3.1 socratic (변경)

**추가 입력:** roots.md 내용 + 최근 세션 1개의 나침반

**추가 질문 유형:**

| 트리거 | 질문 예시 |
|--------|----------|
| 뿌리 반복 감지 | "이전에도 '과부하'가 등장했어요. 그때와 지금, 뭐가 달라졌나요?" |
| 표면 변형 감지 | "말은 다르지만 비슷한 패턴이 보여요. 혹시 연결된다고 느끼시나요?" |
| 시간 간격 큼 | "지난번에 '다음 한 걸음'으로 OO를 제안받았는데, 해보셨나요?" |
| 해소된 뿌리 참조 | "예전에 OO는 해소되었는데, 그때 뭐가 도움이 됐나요?" |

기존 소크라테스식 질문은 그대로 유지. 과거 context가 있을 때 **추가 질문 레이어**가 생기는 것. 첫 세션(roots.md 없음)이면 기존과 동일하게 동작.

### 3.2 crystallizer (변경)

**추가 입력:** roots.md 내용

**추가 책임:**
1. 새 표면→뿌리 맵을 기존 roots.md와 매칭
2. 매칭 결과에 따라 roots.md 갱신
3. 세션 파일에 궤적 섹션 출력

**뿌리 매칭 메커니즘:**
- 별도 알고리즘이 아닌 crystallizer(opus)의 맥락 기반 판단에 위임
- roots.md 전체를 context로 받고:
  1. 새 뿌리가 기존 뿌리와 본질적으로 같은지 판단
  2. 같다면 → 기존 뿌리에 표면 변형 추가, 추이 갱신
  3. 다르다면 → 새 뿌리 등록
  4. 애매하면 → 세션 파일에 `연관 가능: {뿌리명}` 표시, 다음 세션에서 재판단

**애매한 연관의 생명주기:**
- 2회 연속 세션에서 같은 연관이 감지되면 → 매칭으로 승격
- 3회 세션 동안 재등장하지 않으면 → 연관 표시 삭제

**roots.md 갱신 방식:**
- crystallizer가 roots.md 전체를 읽고, 업데이트된 버전을 메모리에서 구성한 뒤 전체 파일을 다시 쓴다
- 이전 버전은 별도 보존하지 않음 — 세션 파일이 감사 추적(audit trail) 역할

**roots.md가 손상된 경우:**
- 파싱 불가능하면 빈 상태로 취급하고, 세션 파일에 경고 기록
- 세션 종료 시 정상적인 roots.md를 새로 생성

### 3.3 collector (변경 없음)

수집은 판단 없이 있는 그대로.

### 3.4 retrospective (변경)

- 기존: patterns.md 참조/갱신
- 변경: roots.md 참조. `/reflect-review` 시 뿌리 단위로 장기 분석

## 4. 세션 파일 변경사항

### frontmatter 추가 필드

```yaml
matched_roots: [과부하]     # 기존 뿌리와 매칭된 것
new_roots: [완벽주의]       # 이번에 새로 감지된 것
```

### 궤적 섹션 추가

기존 6개 섹션(상태 명명, 본질, 표면→뿌리, 에너지 분배, 나침반, 비유)에 추가:

```markdown
## 궤적
> [!timeline]
> **반복 중**: 「과부하」— 4번째 등장. "시간이 없어" → "번아웃" → "새 프로젝트 욕구" → 이번엔 "다 내려놓고 싶다". 표면은 바뀌지만 뿌리는 3개월째 해소되지 않고 있다.
>
> **새로 감지**: 「완벽주의」— 이번 세션에서 처음 드러남. 과부하와 연관 가능.
>
> **지난 나침반 점검**: 이전 "다음 한 걸음"은 _하루 하나만 선택해서 30분 집중_ 이었다. → 시도했으나 지속하지 못함.
```

배치 순서: 에너지 분배 → **궤적** → 나침반 → 비유
(과거를 짚은 후 방향을 제시하는 흐름)

### 모드별 루프 적용 범위

| 단계 | standard | quick | deep |
|------|----------|-------|------|
| roots.md 로드 | O | O | O |
| 최근 세션 나침반 로드 | O | O | O |
| 뿌리 인지 질문 (socratic) | O (2-3라운드) | O (1라운드) | O (5+라운드) |
| 표면→뿌리 맵 생성 | O | X (생략) | O |
| 뿌리 매칭 + roots.md 갱신 | O | O (본질 진단에서 추출) | O |
| 궤적 섹션 출력 | O (전체) | O (간략: 반복 뿌리만) | O (전체 + 시간축 분석) |

quick 모드: 표면→뿌리 맵은 생략하지만, 본질 진단에서 뿌리를 추출하여 매칭은 수행한다.
deep 모드: 궤적 섹션에 시간축 분석(과거→현재→미래)과 가치관 충돌 맵을 추가한다.

## 5. Context 전달 방식 변경

### reflect 커맨드 변경


## 6. 마이그레이션: patterns.md → roots.md

**트리거:** `/reflect` 커맨드가 Phase 0(수집) 이전에 확인:
- roots.md가 없고 patterns.md가 있으면 → 마이그레이션 실행
- roots.md와 patterns.md 둘 다 있으면 → roots.md만 사용 (이미 마이그레이션 완료)
- 둘 다 없으면 → 첫 세션, 빈 상태로 진행

**마이그레이션 절차:**
1. patterns.md를 읽어 roots.md 초기 데이터로 변환
2. 변환 후 patterns.md는 보존 (삭제하지 않음)
3. 이후 세션부터 roots.md만 사용

**필드 매핑:**

| patterns.md | roots.md | 기본값 |
|-------------|----------|--------|
| 패턴명 | 뿌리 이름 | 직접 매핑 |
| 최초 감지 | 최초 감지 | 직접 매핑 |
| 최근 등장 | 최근 등장 | 직접 매핑 |
| 관련 세션 | 관련 세션 | 직접 매핑 |
| 설명 | 메모 | 직접 매핑 |
| (없음) | 표면 변형 | 빈 리스트 — 다음 세션부터 채워짐 |
| (없음) | 등장 횟수 | 관련 세션 개수로 산출 |
| (없음) | 추이 | `관찰 중` |

## 7. 향후 확장

### Approach C: Three-Layer Memory (roots.md에서 확장)

세션이 충분히 쌓여 roots.md가 비대해지거나, 해소된 뿌리의 성장 서사를 별도로 관리하고 싶을 때 마이그레이션.

```
B (현재)              C (확장 시)
                      recent.md    ← 새로 추가 (최근 3개 세션 요약)
roots.md         →   roots.md     ← 활성 뿌리만 유지
                      growth.md   ← 해소된 뿌리 + 성장 궤적 분리
```

마이그레이션 시:
- `recent.md`: crystallizer가 세션 끝에 최근 3개 세션 요약을 자동 갱신
- `growth.md`: roots.md의 "해소된 뿌리" 섹션을 통째로 이동 + 성장 서사 추가
- `roots.md`: 해소된 뿌리 섹션 제거, 활성 뿌리만 유지

**트리거 기준 (참고):**
- roots.md가 50개 이상의 뿌리를 포함할 때
- 해소된 뿌리가 10개 이상 쌓였을 때
- 사용자가 명시적으로 요청할 때

### Rust 기반 wikilink 파싱 도구 (시각화/인덱싱 단계에서 도입)

현재는 에이전트의 맥락 기반 판단으로 충분. 다음 상황에서 도입 검토:
- 세션이 수백 개 쌓여 에이전트가 roots.md 전체를 context에 넣기 어려울 때
- 웹 UI나 그래프 시각화를 붙일 때

후보 라이브러리:
- **obsidian-parser** (Rust): petgraph 기반 지식 그래프 자동 구축. 1000+ 노트 3ms 미만
- **turbovault-parser** (Rust): 모든 Obsidian 링크 변형 지원. Tantivy 기반 전문 검색 + 그래프 분석
- **obsidian-vault / ov** (Rust CLI): 백링크 탐색, 그래프 시각화 즉시 사용 가능
- **obsidiantools** (Python): NetworkX 그래프 + Pandas. 분석/시각화에 강점
